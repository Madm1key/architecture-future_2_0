# Обоснование конфигурации Terraform - «Будущее 2.0», финтех-домен

## Ресурсы и параметры

### Виртуальная машина `fintech-api`

| Параметр  | Значение            | Обоснование                                                                        |
|-----------|---------------------|------------------------------------------------------------------------------------|
| vCPU      | 2                   | Достаточно для Go/Java API при средней нагрузке; легко увеличить через `resources` |
| RAM       | 4 GB                | Покрывает JVM heap (Go runtime требует меньше) + системные процессы                |
| Boot disk | 20 GB `network-ssd` | SSD обеспечивает низкое I/O-latency для логов и временных файлов                   |
| OS        | Ubuntu 22.04 LTS    | LTS-релиз с долгосрочной поддержкой; широкая экосистема                            |
| NAT       | включен             | VM получает публичный IP для входящего трафика и обращений к внешним сервисам      |

### Отдельный ресурс диска `yandex_compute_disk`

Диск вынесен в самостоятельный ресурс (`yandex_compute_disk`) отдельно от VM. Это позволяет:

- управлять жизненным циклом диска независимо от инстанса (пересоздать VM без потери данных);
- явно задавать тип, зону и образ, не смешивая их с параметрами вычислительного ресурса;
- при необходимости подключить диск к другой VM без изменения конфигурации инстанса.

### Сеть

- **VPC-сеть** `fintech-network` создается отдельно для домена, исключая пересечение адресных
  пространств с другими доменами (медицинским, аналитическим).
- **Подсеть** `10.10.1.0/24` - достаточное адресное пространство для роста домена без реорганизации.

### SSH-доступ

Публичный ключ передается через `file("~/.ssh/id_rsa.pub")` напрямую в `metadata`.

## Декларативный подход и Infrastructure as Code

Использование Terraform обеспечивает:

1. **Воспроизводимость** - конфигурация полностью описывает инфраструктуру; повторный `apply`
   гарантирует одинаковое состояние в любом окружении (dev / staging / prod).

2. **Масштабируемость** - добавление нового домена (фармацевтика, электроника) сводится к
   созданию нового модуля с аналогичной структурой без ручных операций в консоли облака.

3. **Контроль изменений** - конфигурация хранится в Git; каждое изменение инфраструктуры
   проходит code review и оставляет историю (`git blame`, `git log`).

4. **Снижение операционных ошибок** - декларативное описание исключает «ручные» расхождения
   между средами, характерные для императивных скриптов или ClickOps-подхода.
