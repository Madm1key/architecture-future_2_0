# Роадмап изменений - «Будущее 2.0»

## Этап 1 - Фундамент (месяцы 1–3)

**Цель:** согласовать архитектуру, провести границы доменов, запустить событийную шину.

| Шаг | Действие                                                         | Команда                         | Ресурсы                |
|-----|------------------------------------------------------------------|---------------------------------|------------------------|
| 1.1 | Зафиксировать границы доменов и Data Contracts для Kafka-топиков | Архитекторы, Tech Leads доменов | 2 архитектора, 1 мес.  |
| 1.2 | Развернуть Apache Kafka в облаке                                 | Платформенная команда           | 1 DevOps, 2 нед.       |
| 1.3 | Подключить ESB → Kafka (Strangler Fig): трафик финтех-событий    | Финтех-команда + платформа      | 2 разработчика, 1 мес. |
| 1.4 | Развернуть Keycloak/OIDC, настроить базовый RBAC                 | Команда безопасности            | 1 инженер ИБ, 2 нед.   |

**Результат:** архитектурное решение согласовано, первые события финтех-домена идут через Kafka, а
не ESB.

**Бизнес:** промежуточная цель - «архитектурное решение сформировано и согласовано». Kafka и границы
доменов - обязательное условие для всех последующих шагов; без шины нельзя отвязать домены от DWH.

---

## Этап 2 - Платформа данных (месяцы 3–6)

**Цель:** запустить Lakehouse, изолировать медицинский контур, подключить ИИ-домен.

| Шаг | Действие                                                                                  | Команда               | Ресурсы                 |
|-----|-------------------------------------------------------------------------------------------|-----------------------|-------------------------|
| 2.1 | Развернуть S3 + Iceberg + Spark                                                           | Платформенная команда | 2 Data Engineer, 2 мес. |
| 2.2 | Настроить CDC: историческая загрузка из DWH                                               | Платформенная команда | 1 Data Engineer, 1 мес. |
| 2.3 | Вынести Медицинский домен в отдельный контур (PostgreSQL + EHR-сервис)                    | Медицинская команда   | 3 разработчика, 2 мес.  |
| 2.4 | Настроить поток ИИ-домена: доступ к PHI в контуре, публикация обезличенных метрик в Kafka | ИИ-команда            | 2 ML-инженера, 1 мес.   |
| 2.5 | Внедрить dbt для ELT-трансформаций                                                        | Платформенная команда | 1 Data Engineer, 1 мес. |

**Результат:** Lakehouse работает, исторические данные из DWH загружены, PHI изолирован, ИИ-домен
публикует обезличенные метрики.

**Бизнес:** Lakehouse снимает главную боль - отчеты строятся часами. Изоляция медданных
закрывает регуляторный риск. CDC позволяет загрузить историю без остановки работы клиник и
банка.

---

## Этап 3 - Портал и вывод легаси (месяцы 6–12)

**Цель:** запустить self-service портал аналитики, завершить вывод DWH и ESB.

| Шаг | Действие                                                                         | Команда               | Ресурсы                         |
|-----|----------------------------------------------------------------------------------|-----------------------|---------------------------------|
| 3.1 | Развернуть Dremio, подключить к Iceberg/S3, настроить RBAC-интеграцию с Keycloak | Платформенная команда | 1 Data Engineer, 1 мес.         |
| 3.2 | Перенести BI-отчеты с DWH на Dremio (приоритет - управленческая отчетность)      | Аналитическая команда | 2 аналитика, 2 мес.             |
| 3.3 | Вынести финтех-домен полностью на PostgreSQL, отключить DWH-зависимости          | Финтех-команда        | 3 разработчика, 2 мес.          |
| 3.4 | Заменить PowerBuilder на веб-интерфейс клиники                                   | Медицинская команда   | 2 frontend-разработчика, 3 мес. |
| 3.5 | Отключить ESB после перевода всего трафика на Kafka                              | Платформенная команда | 1 DevOps, 2 нед.                |
| 3.6 | DWH переходит в read-only режим, план финального отключения                      | Все команды           | Архитектор, 1 мес.              |

**Результат:** портал самообслуживания запущен, бизнес-пользователи работают с данными
самостоятельно, ESB выведен, DWH в режиме вывода.

**Бизнес:** Dremio реализует ключевую цель - «витрину данных» с self-service. Вывод ESB и DWH
снижает операционные расходы и риски безопасности устаревшего стека. Замена PowerBuilder
устраняет зависимость от редких специалистов.
